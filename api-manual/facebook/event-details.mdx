# Facebook Event Details

Collect detailed public Facebook event data. Results are normalized and billed by the actual saved record count.

```json
{
  "urls": [
    "https://www.facebook.com/events/2255360061870188/"
  ]
}
```

{/* mcp-usage:start */}
## Use with MCP

| Interface | Value |
| --- | --- |
| REST | `POST /v1/facebook/event-details` |
| Compact MCP | `socq_execute` with `endpoint: "facebook/event-details"` |
| Typed MCP | `socq_facebook_event_details` |
| Exact-tool URL | `https://api.socq.ai/mcp?tools=facebook_event_details` |
| CLI | `socq facebook event-details` |

Use the JSON request body above as the nested `input` object for `socq_execute`, or pass the same fields directly to the typed tool. Typed tools also accept `_wait_seconds`, `_result_limit`, and `_idempotency_key`.

<Info>
  A successful submission returns a `task_id`. Continue with `socq_get_task` until the task succeeds, then read normalized records from `results.items`.
</Info>

See [MCP quickstart](/integrations/mcp) for the complete submission and polling flow.
{/* mcp-usage:end */}

## Standard Result Fields

Poll `GET /v1/tasks/{task_id}?view=standard` for the fixed result contract. The standard view maps source-specific field names and formats to the stable SocQ fields below; it does not infer or enrich values that the source did not provide. For MCP use `view`/`fields` on `socq_get_task` or `_result_view`/`_result_fields` on typed tools; CLI uses `--result-view`/`--result-fields`. Declared fields remain present when their value is `null`; use the task files for complete source data.

| Field | Type | Nullable | Description |
