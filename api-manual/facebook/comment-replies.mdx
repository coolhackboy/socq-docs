# Facebook Comment Replies

Collect public replies for a Facebook comment. Results are normalized and billed by the actual saved record count.

```json
{
  "url": "https://www.facebook.com/NASA/posts/would-you-lie-in-bed-for-60-days-for-scientific-research11-volunteers-did-exactl/1271494461012594/",
  "comment_id": "Y29tbWVudDoxMjcxNDk0NDYxMDEyNTk0XzU4NzcxOTAzMTA0Mjk5MQ==",
  "results_limit": 20
}
```

<Info>
  Pass the stable post URL and parent comment ID. SOCQ finds the parent comment
  across comment pages and resolves the provider reply tokens internally. Legacy
  `feedback_id` plus `expansion_token` input remains supported, but those tokens
  can expire and should not be stored as a reusable request example.
</Info>

## Reply resolution errors

| Error code | Meaning |
| --- | --- |
| `facebook_parent_comment_not_found` | The comment was not found within the supported comment-page search range. Check that the URL and comment ID belong together. |
| `facebook_reply_token_missing` | The parent comment reports replies but does not expose the tokens required by the provider. |
| `facebook_reply_token_expired` | A supplied legacy token has expired. Retry with `url` and `comment_id`. |
| `facebook_reply_token_incompatible` | The provider returned a token that its reply endpoint would not accept. Retry later or use another parent comment. |
| `facebook_reply_upstream_failure` | The upstream Facebook reply service failed. Retry later. |

## Use with MCP

| Interface | Value |
| --- | --- |
| REST | `POST /v1/facebook/comment-replies` |
| Compact MCP | `socq_execute` with `endpoint: "facebook/comment-replies"` |
| Typed MCP | `socq_facebook_comment_replies` |
| Exact-tool URL | `https://api.socq.ai/mcp?tools=facebook_comment_replies` |
| CLI | `socq facebook comment-replies` |

Use the JSON request body above as the nested `input` object for `socq_execute`, or pass the same fields directly to the typed tool. Typed tools also accept `_wait_seconds`, `_result_limit`, and `_idempotency_key`.

<Info>
  A successful submission returns a `task_id`. Continue with `socq_get_task` until the task succeeds, then read normalized records from `results.items`.
</Info>

See [MCP quickstart](/integrations/mcp) for the complete submission and polling flow.
{/* mcp-usage:end */}
